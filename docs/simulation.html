How to read the simulation

  
OS-Buddy is an agent: it does not answer from memory. It repeats a short loop, and every pass of the loop is one step.
    In each step it sends the whole conversation to Gemini, Gemini picks an action (a tool call), the safety policy checks
    the action, the action runs on the computer if it is allowed, and the result goes back to Gemini. The goal is reached when Gemini
    replies with plain text and no tool call. The loop also stops after 30 steps.

Scenarios

    
Safety rules (policy.sh)

      
BLOCK Never runs, not even with --yes: rm -rf on /, ~ or system folders, mkfs, dd onto a device, fork bombs, recursive chmod/chown on /.

      
ASK Needs a human “y”: anything not on the read-only list, redirects, $( ), backticks, background jobs, private paths (.ssh, .env, keys), every file write or edit.

      
ALLOW Runs on its own: every part of the command starts with a read-only program (ls, du, grep, sort…).

    

    
The three run modes

      
Human at the terminal. Approvals and questions are asked; you answer with the buttons or the keys y, n, a, o.

      
--yes. Every “ask” is approved automatically. “Block” still blocks.

      
No terminal (cron). Nobody can answer, so every “ask” is a no, ask_user fails, and the answer is printed as plain Markdown for scripts.
